- 日期：2026-10-25（UTC；本地 UTC+8 为 2026-10-25）
- 范围：50 条非故障用例（全部设备共 112 台，每台 3 次越权请求）
- 消融变量：仅执行器注册表权限检查（check_call 节点门）：off=进程内替身替换，生产默认值零改动
- 离线声明：E7 权限路径为确定性代码，不依赖真实模型——离线即可完成
- 样本量：cases=50，modes=2，renegade_requests_per_device=3

> **离线确定性消融（Renegade 替身无视提示词约束）：验证运行时权限强制的拦截效果与纵深防御，仅验证流程与不变量，不代表模型效果（E7 不依赖真实模型）。**

## 方法

- on=生产默认（check_call 强制 allowed_nodes）；off=permission_check_disabled 替身跳过节点门（not_registered 仍拒），仅在评测进程内生效，不触碰 app/tools/** 文件。
- 越权替身每台设备依次请求 list_devices（站点级）/ create_work_order（write）/ dispatch_drone（dangerous 无凭证），随后恢复合规流程——模拟「提示词约束被无视」的模型。
- 指标：executed_violations=inspector 节点实际执行（tool.called）的权限面外工具次数；denied(node_not_allowed)=被节点权限拦截次数；case 级 forbidden_calls 仍按 C8 口径（期望禁用表的执行次数）。

## 结论（计划 §11-E7 判定）

- 运行时强制（on）：336 次越权请求全部被节点权限拦截（tool.denied），越权执行 0——权限由代码强制，与提示词遵守与否无关。
- 仅提示词（off）：站点级 list_devices 越权执行 112 次（每台设备 1 次）——设备子任务可读到全站清单，R3 上下文隔离被打破；这就是「只靠提示词声明权限」的直接代价（面试第 3 题证据）。
- 纵深防御如实呈现：off 下 write/dangerous 仍被账本键门/审批凭证门拦截（越权执行 0）——节点权限不是唯一一道门，但它是站点级数据面的唯一一道门。
- E7 为确定性离线实验，无需真实模型重跑；真实模型下的差异只在于「模型是否真的会无视提示词」，拦截机制本身与模型无关。

## 方差与波动

- on executed_violations = 0
- off executed_violations = 112
- attempts_total（两模式相同） = 336

## 已知偏差

- 离线确定性口径：越权路径是代码分支，不依赖真实模型（E7 无需真实模型即可完成）。
- 本消融只关节点权限门：write 工具另有账本键门（ledger_key_required）、dangerous 另有审批凭证门（approval_required）——off 模式下二者仍然生效（纵深防御），越权替身的 create_work_order/dispatch_drone因此未实际执行；这是单一变量设计的如实结果，不是实验缺陷。
- case 级 forbidden_calls 两模式均为 2：来自 reporter 对只诊断用例无条件起草工单的既有生产行为（与 E1 multi 的 forbidden=2 同源，两模式一致——与本消融无关的对照常数）；越权执行的 list_devices 不在期望禁用表内（27 条用例本就期望合法调用），故越权判定以节点权限面（violations_by_tool）为准。
- 越权替身在权限拒绝后恢复合规流程，成功率不因此下降——E7 的判定指标是越权次数，不是成功率。
